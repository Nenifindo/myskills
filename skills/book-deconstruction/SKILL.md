# 拆书技能 (Book Deconstruction)

## 概览

将一本完整的书籍拆解为结构化的章节级笔记，包含核心要点提炼、概念拆解、深度解读，并生成大纲级别的思维导图。输出为 Markdown 文档 + MarkMap 思维导图源代码。

## 工作方式

### 分析框架

本技能包含一个分析框架参考文件 `references/analysis-framework.md`，加载后按其中的维度执行拆解。

### 详细步骤

#### 步骤 1：获取书籍内容

根据用户提供的输入来源，选择对应的方式获取书籍内容：

**来源 A：PDF 文件**
- 使用 Read 工具直接读取 PDF 文件（支持逐页解析）
- 也可使用 `summarize` skill 或 `markdown-converter` skill 辅助提取文本内容
- 对于扫描版 PDF，提醒用户需先进行 OCR 处理

**来源 B：书名/关键词**
- 使用 WebSearch 搜索该书的完整信息（作者、目录结构、核心内容概要）
- 优先搜索格式如：`《书名》 目录 章节`、`书名 summary chapter-by-chapter`
- 获取足够信息后，判断是否能还原章节级结构
- 对于知名书籍，可以搜索读书笔记、知识图谱等辅助材料

**来源 C：URL 链接**
- 使用 WebFetch 获取页面内容
- 判断是否为免费电子书、书评、或百科类页面
- 整合多方来源信息

**来源 D：电子书文件（epub/mobi 等）**
- 先用 `markdown-converter` skill 尝试转换
- 如果不支持，尝试用 Python 脚本提取文本内容（如使用 `ebooklib`、`mobi` 等库）

#### 步骤 2：建立书籍结构

在获取内容后，建立完整的章节结构：

- 提取全书目录（各章、各节名称和层级关系）
- 识别书籍的总-分结构（递进、并列、还是其他）
- 记录各章的大致篇幅和重要程度
- 确认全书共有多少章、多少个主要的节

#### 步骤 3：逐章逐节分析

加载 `references/analysis-framework.md` 获取完整的分析框架。

对每一章进行分析时（如果单章较长则拆到节级别）：

**3.1 核心要点**
- 提取该章的核心论点（1-3 个一句话可概括的结论）
- 提炼支撑论点的关键论据和案例
- 记录该章引入的重要概念和术语
- 标注与前后章节的逻辑联系

**3.2 概念拆解**
- 对核心概念给出清晰定义
- 辨析相近概念（如果存在）
- 用类比或示例帮助理解
- 明确概念之间的逻辑关系（因果、层次、对立等）

**3.3 深度解读**
- 还原作者的论证逻辑链
- 指出隐含假设和前提
- 与领域内其他观点做横向对比
- 客观评价该章的贡献和局限
- 补充个人（即 WorkBuddy 作为分析者）的批判性思考

**3.4 实践与应用**（如内容适用）
- 抽象理论如何落地？
- 具体的行动方案或决策原则
- 适用场景和限制条件

**3.5 金句与记忆点**
- 原文的重要引用或精炼表述

#### 步骤 4：生成 Markdown 文档

按照 `references/analysis-framework.md` 中的 Markdown 结构规范输出文档。

输出格式要求：
- 用中文撰写全文（除非书籍本身是英文且用户要求保留原文引用）
- 层级清晰，使用 `#` → `##` → `###` → `####` 层级结构
- 要点用无序列表 `-` 呈现，不使用数字编号
- 关键术语可以加粗标注
- 深度解读用普通段落呈现，与要点列表区分开
- 章节之间用 `---` 分隔
- 文档末尾包含"全书总结"部分

#### 步骤 5：生成思维导图

使用 `read_me`（modules: "diagram"）和 `show_widget` 工具生成 SVG 思维导图。

思维导图设计规范：
- **中心节点**：书名，居中显示
- **第一层**：各章标题（用不同颜色区分）
- **第二层**：每章的核心要点（每个要点 5-10 字短语）
- **第三层**（可选）：关键概念或深度洞察
- **颜色方案**：按章节分配不同色系，保持整体协调
- **节点样式**：圆角矩形，文字居中
- **A4 阅读优化**：布局横向展开，保持可读性
- 如果书籍结构复杂（10+ 章），考虑分成多个小图或仅展示顶层要点

思维导图每次展示 1 张全局面图即可，不必逐章拆分。

### 关键原则

1. **"拆">"抄"**：拆书的目的是提炼和解读，不是原文搬运。不要大段复制原文，而是用自己的语言重新组织和表达。
2. **结构为王**：好的拆书笔记让人一眼看清全书骨架，比面面俱到的细节更重要。
3. **批判性思考**：不仅要"说了什么"，更要"说得对吗"、"还可以怎么看"。
4. **可读性优先**：输出文档和思维导图都应让读者快速抓住重点，而非沉溺于细节。

## 边界说明

### 触发场景
- 用户提供 PDF 文件并要求分析
- 用户说"拆解《XXX》这本书"或"帮我分析《XXX》"
- 用户说"帮我整理《XXX》的读书笔记"
- 用户说"给《XXX》做一个大纲/思维导图"
- 用户上传电子书文件并要求解读
- 用户提供书籍的 URL 链接并要求分析

### 不适用场景
- 用户只要求"推荐一本书"，没有分析意图
- 用户只要求单段/单页内容的解读（此时应直接回答，不需触发本技能）
- 书籍内容过于敏感或受版权限制无法获取
- 非书籍的文档（如论文、报告）——应由相应技能处理

### 局限性说明

遇到以下情况，诚实告知用户：
- **无法获取全文**：如果仅凭公开信息无法还原完整章节内容，输出 "基于公开信息的概览版" 拆书笔记并标注局限性
- **扫描版 PDF**：无法直接提取文字，建议用户先 OCR
- **内容过大**：如果书籍过长（300+ 页），说明会优先覆盖主要章节，次要章节从简
- **非中文书籍**：对于英文等非中文书籍，用户可选择保留原文引用还是全部翻译
